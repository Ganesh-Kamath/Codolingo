# Codolingo Voice & Tone Guide

Codolingo is designed for people learning to write real software. Its interface speaks with quiet authority, clarity, and genuine respect for the learner's intelligence.

---

## 1. Core Principles

1. **Direct and Actionable**
   State what happened and what to do next. Do not hedge, flatter, or posture.
   - *Instead of:* "Let's unleash your Python superpowers and conquer variables!"
   - *Use:* "Run the script to check how variables store values."

2. **Warm Without Being Cringe**
   Encouragement comes from smooth workflows and clear feedback, not exclamations or cheerleader tropes. No exclamation points as seasoning.
   - *Instead of:* "Awesome job! You're crushing it! Keep the fire burning!"
   - *Use:* "Lesson completed. You earned 25 XP."

3. **No Dev Telemetry or Internal Jargon**
   Internal architecture is an implementation detail. The learner cares about concepts, not our engine state.
   - *Instead of:* "Curriculum Engine telemetry synced", "WASM Pyodide runtime initialized", "MISCONCEPTION_STRING_CONCATENATION"
   - *Use:* "Progress saved", "Python environment ready", "Mixing text and numbers"

4. **Sentence Case Everywhere**
   Buttons, navigation, headers, modal titles, and tooltips use sentence case. All caps is strictly restricted to tiny semantic tags (e.g., `UNIT 1`, `STEP 3`).
   - *Instead of:* "START YOUR CODING JOURNEY NOW", "CHALLENGE WORKSPACE"
   - *Use:* "Start lesson", "Challenge workspace"

---

## 2. Terminology Standard

We adhere strictly to one term per concept across the entire product. Never mix or alternate.

| Concept | Standard Term | Forbidden Terms |
| :--- | :--- | :--- |
| Core unit of learning | **Lesson** | Exercise, problem, quiz, question |
| Unit completion milestone | **Unit challenge** | Capstone synthesis, boss fight, graduation test |
| Curricular grouping | **Unit** | Module, chapter, block |
| Experience metric | **XP** | Points, score, credits, tokens |
| Retention currency | **Streak** | Daily run, fire count |
| Daily target | **Daily goal** | Session target, grind quota |
| Mistake revision | **Review** / **Mistake bank** | Concept repair drill, clinic, weakness ledger |
| Practical build exercise | **Project** | Mission, lab, playground spec |

---

## 3. Feedback and Error Patterns

### Errors
An error message must answer two questions:
1. What went wrong?
2. How do I fix it?

- **Generic Syntax Error:**
  - *Before:* "Oopsie! Python encountered a nasty syntax error! Try debugging your code!"
  - *After:* "Syntax error on line 4. Check for missing closing quotes or parentheses."
- **Empty Code Submission:**
  - *Before:* "Whoa there! Your editor is empty! Write some code to proceed!"
  - *After:* "Write code in the editor before checking your answer."

### Success
Short, concrete confirmation. No confetti bursts for routine single-step answers.
- *Routine step:* "Correct."
- *Lesson complete:* "Lesson complete. +25 XP earned."
- *Unit complete:* "Unit 1 complete. Foundations unlocked."

## 4. Product Name & Wordmark

- **Product Name:** `Codolingo` (One word, Capital C, lowercase o-d-o-l-i-n-g-o).
- **Sub-brand / Tagline:** "Learn Python with immediate feedback."
- Never: `Codolingo Academy`, `Stitch DevRealm`, `PyCodolingo`.
